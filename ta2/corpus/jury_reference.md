# Game of 24: Agentic Reasoning Reference Notes
This is local course reference material, not a benchmark answer key. It contains rules, definitions, and general methods only. It deliberately omits worked answers to the five evaluation cases.

## A. Objective and card identity
The input is a multiset of exactly four card values. Every physical card must be used exactly once even when two or more cards have the same face value. The goal is a fully parenthesized arithmetic expression whose value equals exactly twenty-four. A partial expression that reaches twenty-four before consuming the remaining cards is not a solution. Check the complete expression's leaf constants against the original multiset, not merely the numerical final result. A trustworthy verifier reports both the evaluated value and the number-use check separately.

## B. Allowed syntax and arithmetic
Only addition, subtraction, multiplication, division, integer card literals and grouping parentheses belong to the basic Game-of-24 language. Card concatenation, power, roots, factorial, invented constants, variable names, Python calls, attribute access and executable text are outside the allowed language. Division by zero is illegal, including division by a computed intermediate zero. Subtraction may produce a negative intermediate value. A division may produce a rational intermediate value, even when every original card is an integer. All legal operations must obey the card-consumption rule.

## C. Arithmetic as a state transition
A search state is a finite list of remaining arithmetic terms, each paired with its exact value and the expression from which it was derived. A legal move chooses two different terms and combines them using an allowed operation; then it replaces the chosen pair with one composite term. Therefore each move reduces the number of terms by exactly one. Four cards require precisely three binary combination moves to reach a terminal one-term expression. The transition function should return the intermediate expression and value so a verifier can reconstruct the provenance of the answer.

## D. Distinct operator directions
Addition and multiplication are commutative: swapping the same operands does not change their value. Subtraction and division are not commutative, so both operand orders may need to be searched. For an ordered pair a and b, legal possibilities include a+b, a*b, a-b, b-a, and, when denominators are nonzero, a/b and b/a. Equivalent value states can be deduplicated to conserve computation, but expression provenance should remain available for the successful path. Never silently remove reverse division or reverse subtraction merely to simplify the search.

## E. Linear reasoning baseline
A one-path baseline chooses one arithmetic move at each step and commits to the resulting state. This is computationally economical and easy to explain, but it can make an irreversible choice. Choosing the intermediate value numerically closest to twenty-four is only a heuristic: a locally attractive move may leave no legal continuation with the other cards. A linear baseline should record its actions, final expression, independent validity and elapsed time. A failed attempt means that method did not find a solution; it does not prove that the instance has no solution.

## F. Tree-of-Thought search
Tree-of-Thought represents several candidate arithmetic states as alternative branches. At each depth, the system generates legal moves, evaluates candidates, keeps a bounded frontier and prunes lower-ranked alternatives. The beam width limits cost but can discard a branch that would eventually solve the puzzle. Useful trace fields are branch depth, chosen move, remaining-value state, evaluator score, pruning decision and verifier result. A complete mathematical search differs from bounded heuristic beam search: the latter may fail to find a solution without certifying impossibility.

## G. Agent roles and source of authority
A Proposer suggests one or more complete expressions. An Evaluator ranks only supplied candidates, using available feedback and exact tool assessments, rather than changing the problem. A Verifier parses the selected expression with a restricted grammar, checks every card exactly once and computes the exact result. The supervisor selects which role or tool runs next, records events and enforces a maximum hop count. A language model's confidence score is not mathematical proof. Only the independent verifier may mark a candidate as a verified Game-of-24 solution.

## H. Exact fractions and independent checks
Binary floating point can approximate rational values; exact rational arithmetic avoids ambiguity when multiple divisions are nested. A Fraction-style representation stores a numerator and denominator and automatically normalizes arithmetic operations. An expression should be accepted only if its terminal rational value equals the exact integer twenty-four and all leaf integers match the input multiset. A safe abstract syntax tree parser must reject unsupported nodes such as names, function calls, powers, attributes and comparisons. Safety validation and mathematical correctness are separate tests and both must pass.

## I. Supervisor budgets and termination
A supervisor hop is one dispatch to a role or tool. Bound the total dispatches and preserve that budget across a resumed execution to prevent indefinite loops. Reserve enough remaining hops to evaluate and verify any new proposal before starting a cycle. Normal terminal outcomes include verified, no valid answer within the budget, tool failure, bounded-search exhaustion and complete-search proof of no solution. These outcomes must not be conflated: an exhausted model budget is inconclusive. A proof of impossibility requires complete enumeration under the stated rules.

## J. Short-term and long-term memory
A LangGraph checkpointer associates execution state with a thread identifier so the next turn and a resumed process can access earlier state. A separate persistent Store can hold verified results under namespaced keys, such as a user or group namespace and a canonicalized puzzle. Keeping verified memory separate from unverified proposals reduces error propagation. To demonstrate short-term memory, ask a follow-up that depends on the saved previous turn, then compare it with a new thread without that history. To demonstrate long-term durability, close the process, reopen the same database and read the saved verified result.

## K. Retrieval-augmented generation
A retrieval index converts document chunks into embedding vectors and matches a question against nearby chunks. Nomic text embeddings are computed locally through Ollama; a persistent Chroma collection stores those vectors and their source metadata. A grounded answer should cite retrieved source material and explicitly say "I don't know" when the material does not support the question. Comparing k=1 and k=3 illustrates the effect of context quantity on evidence coverage and answer quality. Nearest-neighbor similarity alone is not a license to invent facts or reveal unrelated private information.

## L. Prompt injection and tool failures
Retrieved documents are lower-trust data, not system instructions. A document may contain malicious instructions such as "ignore the verifier" or fabricated answers, so the agent must keep its fixed rules and independent validation authoritative. HTTP failures, model timeouts, malformed JSON, broken embeddings, empty indexes and locked databases should return explicit error states and bounded retry information. Hybrid search can repair an invalid arithmetic proposal, but it must not silently hide a broken required model call. Testing both an approved valid answer and a rejected invalid answer makes guardrails observable.

## M. Fair comparison and transparency
The same puzzle inputs, card rules, seeds, model, and machine should be held constant when comparing strategies. Report verified success, invalid acceptance, time, generated tokens, tool calls, search nodes, hop count and whether an exact oracle contributed an answer. Model-only and tool-assisted results belong in different columns or explicit mode labels. A small set of puzzles with one random seed is descriptive evidence rather than a general proof of superiority. If a harder method consumes more computation but does not improve accuracy, that negative result is meaningful and should be reported rather than hidden.

## N. Boundaries of the demonstration
A local Streamlit dashboard shows observed status, candidate provenance, role events, retrieved source snippets and checkpointed history. A successful live run proves that this particular configuration can produce a checked answer, not that it will solve every possible card multiset. The corpus gives general rules and strategies; it must not embed benchmark solutions that leak the expected results. Namespaces separate application records but are not authentication boundaries against someone with local filesystem access. Model-only failure and deterministic fallback should be labelled independently for an honest jury demonstration.
